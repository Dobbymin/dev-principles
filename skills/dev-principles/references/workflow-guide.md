# 적응형 개발 워크플로 & 규칙 학습 루프 (`workflow-guide`)

모든 작업에 동일한 무거운 절차를 강제하지 않는다. 작업 규모와 위험도에 따라 **Track S / Track M / Track L** 중 적절한 트랙을 선택해 실행한다.

## 1. 작업 규모별 3트랙 워크플로

### Track S: 소규모 수정 · 단순 버그픽스 (1~2개 파일, 경계 변경 없음)
1. **컨텍스트 확인**: `.dev-principles.yaml`, 기존 파일 컨벤션만 빠르게 확인한다.
2. **기준선 확보 (`TEST-02`)**: 버그 수정이면 가능할 때 실패 재현 테스트를 먼저 작성한다.
3. **최소 수정 (`AI-02`, `AI-03`)**: 요청과 직접 연결된 줄만 외과적으로 수정한다.
4. **최신 검증 (`TEST-03`)**: 관련 테스트·타입체크·린트 및 `dev-principles check`를 실행해 실제 출력으로 완료를 확인한다.

### Track M: 표준 기능 구현 · 리팩터링 (여러 파일, 새 모듈/훅/컴포넌트)
1. **요구사항·모호성 점검 (`AI-01`)**: 숨은 가정이나 다중 해석 지점이 있으면 구현 전에 질문한다.
2. **구조 탐색**: `structure-analyzer`로 디렉터리 구조, 활성 프리셋, 기존 도구(`tsc`/린트/테스트), `[Conflict]`를 파악한다.
3. **버전 API 확인 (`AI-05`)**: 버전 민감 라이브러리가 관여하면 Context7 MCP(`resolve-library-id` → `query-docs`) 또는 `package.json`/`.d.ts`로 시그니처를 확인한다.
4. **경량 설계**: 파일 배치(`SOC-*` 및 활성 프리셋), 타입 계약(`TS-01`), 검증 계획을 짧게 확정한다.
5. **TDD/최소 구현 (`TEST-02`, `AI-02`)**: 작은 단위로 구현하고 핵심 동작의 단위/통합 테스트를 함께 작성한다.
6. **검증 및 리뷰 (`TEST-03`)**: `node bin/dev-principles.mjs check`, 프로젝트 테스트/타입/린트 실행 후 `principles-reviewer`로 변경 diff를 점검한다.

### Track L: 복합 신규 기능 · 아키텍처 변경 · 보안 민감 변경
1. **요구사항·범위·리스크 명세 (`AI-01`)**: 목표, 비목표(non-goals), 보안/데이터 경계, 모호한 트레이드오프를 사용자와 확정한다.
2. **아키텍처·단계 분해 (`AI-04`)**: 책임 경계와 계약을 설계하고, `[단계] → verify: [검증 방법]` 형식의 작은 작업 단위로 분해한다.
3. **컨텍스트 오염 방지 실행**: 탐색·리뷰 등 읽기 전용 작업은 서브에이전트(`structure-analyzer`, `principles-reviewer`, `architecture-reviewer`, `security-reviewer`)에 분리 위임해 주 작업 컨텍스트를 깨끗하게 유지한다.
4. **단계별 구현 및 게이트 검증**: 각 단계 완료 시 해당 검증 명령을 통과시킨 뒤 다음 단계로 진행한다.
5. **다각도 최종 검증 (`TEST-03`)**: 전체 테스트·빌드·정적 검사 결과를 확인하고, 남은 리스크와 미검증 영역을 솔직하게 보고한다.

## 2. 제안 전용 규칙 학습 루프 (Proposal-Only Rule Evolution)

반복되는 실수나 프로젝트 예외가 발견되더라도 AI가 임의로 `.dev-principles.yaml`이나 규칙 문서를 수정해서는 안 된다. 반드시 아래 **제안 전용 루프**를 따른다.

```text
문제/반복 패턴 발견 → 개선안 제안서 작성 → 실제 근거(파일/라인/빈도) 기록 → 사용자 명시적 승인 → 설정/규칙 반영
```

### 제안서 표준 형식 (`/dp-propose`)
- **대상**: `.dev-principles.yaml` 오버라이드 / `customPrinciples` 추가 / `ignore` 등록 / 코어 규칙 제안
- **관찰 근거**: 반복 발생 위치(파일:라인), 기존 규칙과 충돌 또는 오탐 사례
- **제안 내용**: 변경 전/후 diff 초안 및 예상 오탐·호환성 영향
- **결정 요청**: 사용자 승인 대기 (승인 전 파일 수정 금지)
