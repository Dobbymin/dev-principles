# 테스트 & 검증 원칙 (`TEST-*`)

### `TEST-01` 구현 세부가 아닌 관찰 가능한 동작·계약 중심 테스트
- **강도**: `SHOULD`
- **자동화**: `manual` — 내부 상태/구현 결합 테스트 및 순수 로직 분리 여부 리뷰
- **적용 범위**: 단위·통합·컴포넌트 테스트
- **규칙**: 내부 state 변수명, private 메서드 호출 횟수, CSS 클래스 세부 구현에 결합된 취약한 테스트 대신, 입력 대비 출력과 사용자·호출자가 관찰 가능한 동작(접근 가능한 역할/라벨, API 계약, 상태 전이)을 검증한다. 복잡한 도메인 계산은 UI에서 분리해 순수 함수 단위 테스트로 검증한다.
- **이유 (Why)**: 구현 세부에 묶인 테스트는 리팩터링할 때마다 깨져 테스트 신뢰도를 떨어뜨린다.
- **예외 / 오탐 방지**: 레이아웃 회귀 방지가 목적인 전용 스타일시트/스냅샷 회귀 테스트나 성능 측정 테스트는 예외로 허용한다.
- **Before / After**:
```ts
// Bad: 내부 헬퍼 호출 횟수만 검증하고 실제 출력 결과는 확인하지 않음
expect(internalNormalizeSpy).toHaveBeenCalledTimes(1);

// Good: 공개 계약(입력 -> 기대 출력/부수효과)을 검증
expect(calculateOrderTotal([{ price: 1000, qty: 2 }], "VIP")).toBe(1800);
```

### `TEST-02` 버그 수정 및 핵심 도메인 로직의 회귀 테스트 선행 (TDD)
- **강도**: `SHOULD`
- **자동화**: `manual` — 버그 수정·도메인 로직 PR에 대응하는 테스트 포함 여부 리뷰
- **적용 범위**: 버그 수정, 핵심 비즈니스 규칙, 상태 머신, 유틸리티/CLI 구현
- **규칙**: 버그를 수정할 때는 먼저 버그를 재현하는 실패 테스트(Red)를 작성해 실패를 확인한 뒤 최소 수정으로 통과(Green)시키고 정리(Refactor)한다. 핵심 도메인 로직과 파서/상태 전이도 테스트와 함께 구현한다.
- **이유 (Why)**: 실패 재현 테스트 없이 수정하면 같은 버그가 재발하고, 테스트가 실제로 버그를 잡는지 증명할 수 없다.
- **예외 / 오탐 방지**: 순수 정적 마크다운 문서 수정, 일회성 탐색 프로토타입, 테스트 인프라가 없는 외부 설정 파일 변경은 예외로 둔다.
- **Before / After**:
```text
// Bad: 버그 수정 후 기존 테스트만 돌리고 새 회귀 케이스는 추가하지 않음

// Good:
// 1. [Red] skipAuthRefresh 누락 시 401 무한 재시도 재현 테스트 작성 -> 실패 확인
// 2. [Green] skipAuthRefresh: true 적용 -> 테스트 통과 확인
```

### `TEST-03` 완료 선언 전 최신 검증 근거 확보 (Verification Before Completion)
- **강도**: `MUST`
- **자동화**: `automated` — 수정 후 테스트·타입체크·린트·빌드·`dev-principles check` 실행
- **적용 범위**: 모든 코드 수정·리팩터링·버그 수정 완료 보고
- **규칙**: 작업을 완료했다고 보고하기 전에, 마지막 편집 이후의 최신 상태에서 해당 프로젝트의 관련 검증 명령(`tsc`, 린트, 테스트, 빌드, `dev-principles check`)을 직접 실행하고 실제 통과 결과를 확인한다. 실행하지 못했거나 환경 제약으로 생략된 검증은 통과로 보고하지 않고 미확인 범위를 명시한다.
- **이유 (Why)**: 이전 턴의 기억이나 부분 테스트 통과만으로 완료를 선언하면 마지막 수정에서 발생한 컴파일·회귀 오류를 사용자에게 넘기게 된다.
- **예외 / 오탐 방지**: 읽기 전용 분석/리뷰 작업이나 사용자가 명시적으로 실행을 보류한 경우는 "미실행(읽기 전용)"으로 상태를 정확히 표기한다.
- **Before / After**:
```text
// Bad: "수정 완료했습니다. 모든 테스트가 통과할 것입니다." (실행 근거 없음)

// Good: "마지막 수정 후 `npm run check` 실행 결과 10/10 테스트 통과, `tsc --noEmit` 0 errors 확인. (실제 디바이스 PWA 설치 캐시는 미검증)"
```
